# PaperFlow

영어 학술 논문 PDF를 한국어로 번역하는 Netlify 사이트.

## 동작 구조

```
브라우저                                    Netlify Function
────────                                    ────────────────
1. PDF 선택
2. pdf.js로 텍스트 추출 (로컬)
3. 정리·구간 분할 (로컬)
4. 용어집 요청           ──────────────▶  task: glossary  ──▶ OpenAI
5. 구간별 1차 번역       ──────────────▶  task: draft     ──▶ OpenAI
6. 구간별 2차 교차검증   ──────────────▶  task: review    ──▶ OpenAI
7. 결과 표시 / Markdown·PDF 저장
```

**텍스트 추출을 브라우저에서 하는 이유.** Netlify 함수의 요청 본문 상한은 6MB이므로
논문 PDF 자체를 함수로 올리는 방식은 구조적으로 불가능하다. 브라우저에서 추출하면
텍스트 수십 KB만 전송되고, `pdf-parse` 의존성도 사라진다.

**구간을 나눠 호출하는 이유.** 함수 한 번의 실행 시간이 짧기 때문에(무료 플랜 기준 10초)
논문 전체를 한 번에 번역할 수 없다. 각 요청은 입력만으로 결과가 정해지므로 실패한 구간은
그대로 재시도할 수 있고, 응답이 잘리면 구간을 절반으로 쪼개 다시 시도한다.

## 파일

| 경로 | 역할 |
| --- | --- |
| `index.html` | 화면과 스타일 (`@media print`가 "PDF로 저장"을 담당) |
| `assets/pdf-text.js` | PDF → 정리된 텍스트. 단 나누기, 문단 복원, 머리말·페이지번호 제거 |
| `assets/translator.js` | 용어집 → 1차 번역 → 교차검증 오케스트레이션 |
| `assets/app.js` | 파일 선택, 진행 표시, 결과 렌더링 |
| `netlify/functions/translate.mjs` | OpenAI 호출. 프롬프트는 전부 서버에 있다 |
| `vendor/pdfjs/` | pdf.js 6.2.108 브라우저 빌드 (번들러 없이 직접 로드) |

## 환경 변수

| 이름 | 필수 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `OPENAI_API_KEY` | ✅ | – | OpenAI API 키 |
| `OPENAI_MODEL` | | `gpt-5.6-luna` | 사용할 모델 |
| `OPENAI_REASONING_EFFORT` | | `low` | `none`/`low`/`medium`/`high`/`xhigh`/`max` |
| `RATE_LIMIT_PER_MINUTE` | | `150` | IP당 분당 요청 수. `0`이면 해제 |

## 논문 번역에 맞춘 처리

- **단 나누기 인식** — 2단 조판을 감지해 왼쪽 단을 모두 읽고 오른쪽 단으로 넘어간다.
  이 처리가 없으면 두 단이 한 줄씩 번갈아 섞여 문장이 무너진다.
- **문단 복원** — 첫 줄 들여쓰기, 또는 오른쪽 여백에서 짧게 끝난 줄을 근거로 문단 경계를
  되살린다. 글자 크기가 바뀌는 지점도 경계로 본다(머리말 / 제목 / 본문 구분).
- **제목 인식** — 번호(`3.1 Method`), 표준 제목명(Abstract, References …), 본문보다 큰
  글자 크기를 근거로 판단한다.
- **머리말·꼬리말·페이지 번호 제거** — 여러 페이지에 반복되는 줄을 찾아 지운다.
- **줄바꿈 하이픈 복원** — `trans-` + `lation` → `translation`. 단, 문서 안 다른 곳에
  하이픈째로 등장하는 복합어는 하이픈을 유지한다.
- **참고문헌 미번역** — References 이후는 번역하지 않고 원문 그대로 따로 보여준다.
- **용어집 선행 생성** — 초록·서론·제목에서 핵심 용어를 먼저 뽑아 모든 구간에 전달하므로
  같은 용어가 구간마다 다르게 번역되지 않는다.
- **실제 교차검증** — 2차 패스는 원문과 1차 번역을 함께 받아 누락, 숫자·인용 일치, 용어집
  준수, 문체 일관성을 점검하고 교정본을 낸다.
- **문체 규칙** — 논문체 평서형(`~이다`, `~한다`). 인용 표시·수식·단위·고유명사·데이터셋명은
  원문 유지. `Figure 3` → `그림 3`, `Section 4` → `4절`.

## 한계

- 스캔한 이미지 PDF는 지원하지 않는다(OCR 없음). 추출 글자 수가 200자 미만이면 안내한다.
- 본문 30만 자를 넘으면 장을 나눠 올려야 한다.
- 표와 그림 내부의 텍스트는 문단으로 섞여 들어올 수 있다.
- 줄바꿈 하이픈이 진짜 복합어 하이픈이고 문서에 한 번만 등장하면 하이픈이 사라질 수 있다.
- 인증이 없으므로 `RATE_LIMIT_PER_MINUTE`만으로 API 비용을 막는다. 공개 운영 시에는
  별도 인증을 붙이는 편이 안전하다.

## 개발

```bash
npm install
npx netlify dev
```

pdf.js를 올릴 때:

```bash
npm install pdfjs-dist@<version> --no-save
cp node_modules/pdfjs-dist/build/pdf.min.mjs vendor/pdfjs/
cp node_modules/pdfjs-dist/build/pdf.worker.min.mjs vendor/pdfjs/
```
